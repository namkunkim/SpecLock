# 출처 불명 조건

명세화 과정에서 발견했으나 **왜 존재하는지 근거를 찾지 못한** 조건들.

이 목록은 폐기 대상이 아니라 **추적 대상**이다. 두 가지 이유로 유지한다.

1. 근거를 모른다고 해서 불필요한 것은 아니다. 오히려 과거 이슈 대응으로 급하게 들어간 조건일 가능성이 있고, 그런 것이 리팩토링 때 가장 잘 삭제된다.
2. **이 목록의 크기 자체가 보고할 만한 발견이다.** "이 모듈의 조건 N개 중 M개는 근거를 추적할 수 없다"는 명세 부재의 정량적 증거다.

---

## 미해결

| # | 위치 | 조건 | 관측 결과 | 관련 UC | 추적 시도 | 상태 |
|---|---|---|---|---|---|---|
| 1 | `File.kt:120` | | | UC-XXX-01 | git blame 확인 / 팀 문의 예정 | 미해결 |

**추적 시도** 칸을 채우면 같은 조건을 두 번 조사하지 않는다.

## 해결됨

근거를 찾은 항목은 여기로 옮기고, BR로 승격했다면 ID를 적는다.

| # | 조건 | 밝혀진 근거 | 처리 |
|---|---|---|---|
| | | 이슈 #12847 | BR-XXX-014로 승격 |
| | | 근거 없음 확인 (팀 확인 완료) | 제거 대상으로 분류 |

---

## 추적 방법

```bash
# 해당 라인이 언제 왜 추가되었는지
git log -L <시작>,<끝>:<파일>

# 이슈 번호가 붙은 커밋
git log --grep='#[0-9]\+' --oneline -- <파일>

# 커밋 메시지 전체
git log --format='%h %an %ad %s' -- <파일>
```

git 이력으로 안 나오면 팀 문의 대상이다. 문의해도 아무도 모른다면 그것 자체를 기록한다 — 그 조건은 다음 리팩토링에서 반드시 삭제될 것이므로, 삭제해도 되는지 판단할 근거를 지금 만들어두는 것이 낫다.
