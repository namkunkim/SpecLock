# Phase A — 스코프 정의 + 모듈 스캔 → UC 후보 도출

**목적**: 명세 대상 범위를 확정하고, 그 범위에 어떤 유스케이스가 있는지 목록화한다. 확정이 아니라 후보 제시.
**주체**: AI 주도, 사람이 범위·묶기/쪼개기/삭제만 지시.

---

## A-0. 스코프가 응집된 단일 모듈이 아니라면 먼저 정의한다

프로젝트가 크면 담당 범위가 패키지 하나로 안 끝나고, **특정 클래스 + 명시된 패키지들** 같은 비연속 조합인 경우가 흔하다. 이 경우 Phase A를 UC 도출로 바로 시작하지 말고, 범위부터 선언한다.

**단일 패키지/모듈이 명세 대상과 정확히 일치하면 A-0을 건너뛰고 A-1로 간다.**

### 프롬프트 (A-0)

```
아래 대상들을 명세 범위로 잡으려 한다.

대상 목록:
- <클래스 또는 패키지 1>
- <클래스 또는 패키지 2 (패키지 전체면 *로 표기)>
- 제외: <같은 영역인데 뺄 것>

templates/scope.md 형식으로 범위 정의서를 작성해줘.

특히:
1. 포함 대상과 제외 대상을 표로 정리
2. 포함된 클래스들이 서로 호출·의존하는 관계를 확인해
   스코프 안에서 응집되어 있는지, 아니면 서로 무관한 클래스들이
   억지로 묶인 것인지 판단해서 알려줘 (후자면 스코프를 나누는 게 나을 수 있다)
3. 포함된 클래스가 스코프 밖 클래스를 호출하는 지점을 찾아
   "경계를 넘는 의존성" 표에 채워줘. 그 밖의 클래스는 따라 들어가지 마라

확정하지 말고 초안으로 제시해. 포함/제외 이유가 자명하지 않은 항목은
질문 형태로 물어봐줘.
```

### 사람이 할 일

- 포함/제외 판단에 대한 질문에 답한다
- 응집도가 낮다는 지적이 나오면 스코프를 나눌지 결정한다
- 경계를 넘는 의존성이 과도하게 많으면(예: 10개 이상) 범위 재조정을 고려한다

### 결과물

`docs/spec/scope.md` 확정. 이후 모든 Phase에서 "모듈"이라는 표현은 이 스코프를 가리킨다.

## A-1. UC 후보 도출

## 프롬프트

```
너는 레거시 코드에서 유스케이스를 역추출하는 분석가야.

대상 스코프: <docs/spec/scope.md 경로, 또는 A-0을 생략했다면 모듈 경로 직접 명시>

이 스코프의 진입점(Activity/Fragment/ViewModel/public API/이벤트 핸들러)을 찾고,
사용자 또는 외부 시스템 관점의 유스케이스 후보를 도출해줘.

각 UC마다 표로:
| 제안 ID | 한 줄 설명 | 관련 파일 | 분기·예외 대략 수 | 외부 의존성 |

작성 규칙:
- 클래스 하나 = UC 하나가 아니다. 사용자가 인지하는 목적 단위로 묶어라.
  "EditViewModel"이 아니라 "편집 화면 진입"이다.
- 설명에 클래스명을 쓰지 마라. 클래스명이 필요하다면 그건 UC가 아니라
  구현 단위일 가능성이 높다.
- 내부 유틸리티, 헬퍼, 데이터 변환기는 UC가 아니다.
- 확신이 낮은 항목은 [불확실]로 표시하고 이유를 적어라.
- 외부 의존성은 네트워크/DB/파일/다른 모듈 중 해당하는 것을 적어라.
- scope.md 가 있다면 "경계를 넘는 의존성" 표의 대상은 UC 후보에 넣지 마라.
  그건 이미 경계 밖으로 분류된 것이다.

확정하지 말고 후보로만 제시해. 내가 묶기·쪼개기·삭제를 지시하면 반영해줘.

추가로 마지막에:
- 이 스코프의 책임 경계를 2~3줄로 요약
- 스코프 바깥과 주고받는 것(입력/출력)
```

---

## 출력 예시

| 제안 ID | 설명 | 관련 파일 | 분기 수 | 외부 의존성 |
|---|---|---|---|---|
| UC-EDIT-01 | 편집 화면 진입 및 리소스 확보 | EditViewModel.kt, ResourceRepo.kt | ~14 | 네트워크, 파일 |
| UC-EDIT-02 | 편집 결과 저장 | EditViewModel.kt, SaveUseCase.kt | ~8 | 파일, DB |
| UC-EDIT-03 | [불확실] 편집 취소 및 임시본 정리 | EditViewModel.kt | ~5 | 파일 |

## 사람이 할 일

- 묶기: "1번과 3번은 하나의 UC로"
- 쪼개기: "2번은 저장과 검증이 섞여 있으니 분리"
- 삭제: "5번은 UC가 아님"
- 이름 조정: 사용자 관점 표현으로
