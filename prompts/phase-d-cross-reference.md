# Phase D — 외부 소스 대조

**목적**: 코드에 없는 정보를 끌어와 "이 조건이 의도인가"를 판단할 재료를 만든다.
**주체**: AI 전담.

이 Phase가 없으면 **현재 버그가 정식 명세로 승격된다.** 코드는 "무엇을 하는가"만 알려주고 "무엇을 해야 하는가"는 알려주지 않기 때문이다.

---

## 프롬프트

```
[Phase C 결과]
<분기 목록 붙여넣기>

[외부 소스]
- 시장 이슈 이력: <붙여넣기 또는 경로>
- 기획 문서 / QA 테스트 케이스: <붙여넣기 또는 경로>
- git log (해당 파일): <붙여넣기 또는 명령 결과>

다음을 수행해줘:

1. 각 이슈를 Phase C의 분기 항목에 매핑

2. 어떤 분기로도 설명되지 않는 이슈 → [명세 누락 후보]
   이것이 이 Phase의 가장 중요한 산출물이다.
   코드에 없는 것은 코드를 읽어서는 발견할 수 없으므로
   외부 소스 대조가 유일한 발견 경로다.

3. 어떤 이슈/문서와도 연결되지 않는 분기 → [출처 불명]

4. git log에서 이슈 티켓 번호가 붙은 커밋으로 추가된 분기
   → [이슈 대응 유래]로 별도 표시
   근거가 확실한 BR 후보이며, 동시에 리팩토링 때 가장 잘 삭제되는
   종류이므로 우선 보호 대상이다.

출력:
- 매핑 표
- [명세 누락 후보] 목록  ← 가장 중요
- [출처 불명] 목록
- [이슈 대응 유래] 목록
```

---

## 자료 수집 명령

```bash
# 특정 파일에 이슈 번호가 붙은 커밋
git log --grep='#[0-9]\+' --oneline -- <파일>

# 특정 라인이 언제 왜 추가되었는지
git log -L <시작>,<끝>:<파일>

# 해당 파일의 전체 커밋 메시지
git log --format='%h %s' -- <파일>
```

## 결과 활용

| 분류 | Phase E에서의 처리 |
|---|---|
| 이슈에 매핑됨 | **A. 승격 추천** — 근거 명확 |
| [이슈 대응 유래] | **A. 승격 추천** — 근거 확실, 보호 우선순위 높음 |
| [명세 누락 후보] | **D. 신규 제안** — 사람 결정 필요 |
| [출처 불명] | **B. 보류** — `docs/spec/unknowns.md`에 누적 |

## 외부 소스가 부족할 때

이슈 트래커 접근이 안 되거나 이력이 없다면, git log만으로도 상당 부분 대체된다. 그마저 없다면 대부분의 항목이 `[출처 불명]`으로 분류될 텐데, **그 자체가 보고할 만한 발견이다.** "이 모듈의 조건 N개 중 M개는 근거를 추적할 수 없다"는 명세 부재의 정량적 증거다.
